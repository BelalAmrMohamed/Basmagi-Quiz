### 1. Same-name race condition (explicitly deferred by the prior audit)
`hasQuizNameCollision` (`api/_itemActions.js`) is a pre-check query, not an atomic DB constraint — unlike folders/courses, which are protected by real unique constraints (`folders_unique_name_per_parent`, `courses_unique_slot`) that a concurrent write can't slip past. Two concurrent renames/moves/edits landing on the same quiz title at the same course/folder can both pass the check and both succeed, producing a duplicate. The prior audit's fix-plan section explains why this was left out of scope ("a real fix would need a partial unique index... a schema change"). Design and implement that: a Postgres partial unique index on `quizzes` scoped to `(course_id, folder_id, lower(trim(title)))` (mind that `folder_id` is nullable — a plain unique index treats each `NULL` as distinct, so check whether you need two partial indexes or a `COALESCE`), a new Supabase migration file following the naming/style of the existing ones in `supabase/migrations/`, and update `handleRenameItem`/`handleUpdateQuiz`/`handleMoveItem` in `api/admin.js` to catch the resulting `23505` and return the same friendly error the pre-check already returns (matching how folder/course renames already handle their own `23505`) — keeping the app-level pre-check too isn't wrong (it gives a nicer error without needing to parse the DB error first), but the constraint is what actually closes the race.

### 2. "نسخ لامتحاناتي" copy button — no animation + double-copy on repeated click
From `docs/issues.md`'s "امتحاناتك Rules" section (still unresolved, unrelated to the naming-rule fixes): clicking the copy-to-my-quizzes button on a course/folder shows no loading feedback, so a confused user clicks it again before the first copy finishes, and ends up with the item copied multiple times. Note that `withCopyButtonLoadingState` already exists in `public/src/features/home/copy-to-my-quizzes.js` for exactly this purpose — find out why it isn't preventing this (wrong button reference? not awaited? click handler not disabled/debounced at the point where the click actually originates?) and fix it there rather than adding a parallel mechanism.

### 3. Menus stacking instead of replacing each other
Also from that same `issues.md` section: right-clicking a quiz opens `#userQuizContextMenu`; if the `.exam-more-btn` dropdown (`.exam-dropdown-menu`) is then opened without closing the context menu first, both menus render on top of each other instead of the second one replacing the first (unlike two `.exam-more-btn` dropdowns opened in sequence, which already correctly close-and-replace). Find where each menu's open/close state is managed and make opening either one close the other, so only one menu is ever open at a time.
